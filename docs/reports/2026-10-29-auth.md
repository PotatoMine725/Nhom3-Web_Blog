## Deviations from the plan

- **Validation order in `register`.** The plan says to catch `ValidationError` after `save()`. The code calls `user.validateSync(['username', 'email'])` before the duplicate check instead. The form can then show all errors at the same time (test 8). The code also catches `ValidationError` and error code 11000 during `save()`, as the plan says.
- **Duplicate check.** The code runs the duplicate check only when the field is not empty.
- **Test method.** The plan says to test in a browser. The tests ran as a Node script that sent HTTP requests to the running server. The script read the `users` and `sessions` collections directly. No test used a browser or DevTools.
- **Commit `docs: thêm plan xác thực`** already existed before this work.
- **Test data.** The test script deleted all users with an `@example.com` email before and after the test. The `users` collection was empty before the test (0 users). It is empty after the test (0 users). No collection or database was dropped.
- **Files not in git.** The work created `.env` from `.env.example`. Git ignores this file. Then `npm install` created `node_modules`. The work did not change `package-lock.json`.

### Notes on test 11

A guest does not get a cookie, because `saveUninitialized` is `false`. The "before" cookie in the test was therefore empty. The test shows that a cookie is set after log in. It does not show that `regenerate()` replaces an existing session id. The code calls `req.session.regenerate()` before it sets `userId`. A person must check this in DevTools with a guest session that has a cookie (for example, after a flash message).
